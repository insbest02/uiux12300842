# Amor AI

당신의 연애를 이해하는 AI 대화 코치, **Amor AI** 서비스 웹페이지입니다.
사용자는 고민을 입력해 상황에 맞는 답장을 추천받고, 마음에 드는 답장을 **보관함**에 모아 두었다가 다시 꺼내 쓸 수 있습니다.
새 기능과 코칭 팁은 **소식 알림 신청** 폼으로 받아 볼 수 있습니다.

- 배포 페이지: https://insbest02.github.io/uiux12300842/
- 저장소: https://github.com/insbest02/uiux12300842

## 9주차: 폼 UI와 입력 경험

### 이번 주에 추가·수정한 기능

- 페이지 아래의 이메일 한 칸짜리 "가입" 영역을 **Amor AI 소식 알림 신청 폼**으로 개선했습니다.
  ("가입"이 계정 생성으로 오해될 수 있다는 피드백에 따라 메뉴·제목·버튼 문구를 "알림 신청"으로 통일)
- 신청 후 **"신청 내용 수정"** 경로를 추가해 주소를 잘못 입력했을 때 다시 고칠 수 있습니다.
- 추천 답장에 **"상황별 예시"** 표시를 붙여 실제 대화 분석 결과와 구분하고, **"답장 복사"** 버튼을 추가했습니다. (6주차 탭, 7주차 상담 완료 화면, 보관함 상세)

### 입력 항목과 조건

| 항목 | 요소 | 필수 | 입력 조건 | 입력 중 표시 |
|---|---|---|---|---|
| 이름 또는 닉네임 | text | 필수 | 2~10자 | "N / 10자 · M자 더 필요해요" → "✓ 사용할 수 있어요" |
| 이메일 | email | 필수 | `@`와 `.`이 있는 형식, 이미 신청한 주소는 불가 | "아직 이메일 형식이 아니에요" → "✓ 올바른 이메일 형식이에요" |
| 가장 받고 싶은 소식 | select | 필수 | 4가지 중 하나 선택 | "✓ '답장 추천 팁'을(를) 먼저 보내 드려요" |
| 알림 빈도 | radio | 기본값 있음 | 주 1회 / 새 소식이 있을 때마다 | 고른 항목 강조 |
| 휴대폰 문자로도 받기 | checkbox | 선택 | 체크하면 휴대폰 번호 칸 표시 | – |
| └ 휴대폰 번호 | tel | 체크 시 필수 | 010 등으로 시작하는 10~11자리, 숫자만 쳐도 하이픈 자동 | "N자리 입력 중 · 10~11자리가 필요해요" → "✓ 문자 알림을 받을 수 있는 번호예요" |
| 바라는 점 | textarea | 선택 | 100자 이내 | "✓ N / 100자", 초과하면 바로 오류 |
| 정보 저장 동의 | checkbox | 필수 | 체크 | "✓ 동의했어요" |

- 모든 입력 요소에 `label`을 연결하고, 아래에 회색 도움말(`aria-describedby`)로 조건을 안내합니다.
- 상태는 색(빨강·초록 테두리)과 함께 **✓ / ✗ 문구**로도 구분합니다.
- 오류는 칸을 한 번 입력하고 벗어났거나 제출을 시도한 뒤부터 빨갛게 보여 주고, 올바르게 고치면 그 자리에서 바로 해제됩니다.

### 조건부 입력

| 행동 | 화면 반응 |
|---|---|
| "휴대폰 문자로도 알림 받기" 체크 | 휴대폰 번호 영역이 나타나고 입력칸이 사용 가능(`disabled` 해제), 커서 이동 |
| 체크 해제 | 영역이 사라지고 입력칸이 `disabled` → 검사·제출에서 제외, 오류 문구도 사라짐 |
| 다시 체크 | 전에 입력한 번호가 남아 있어 그대로 이어서 사용 |

### 제출 처리 (`form`의 `submit` 이벤트)

| 상황 | 조건 | 화면 반응 | 다음 행동 |
|---|---|---|---|
| 차단 | 필수값 누락·조건 불충족 | 위쪽에 "확인이 필요한 항목이 N개 있어요: 이름, 이메일…" 요약, 각 칸에 ✗ 오류, 첫 오류 칸으로 커서 이동 | 고치면 요약 개수가 줄고, 모두 고치면 요약이 사라짐 |
| 신청 중 | 모든 조건 충족 | "⏳ 알림 신청을 처리하고 있어요…" 표시, 버튼이 "신청 중…"으로 바뀌고 **신청·다시 작성 버튼 비활성화** (중복 제출 방지) | 약 1초 뒤 결과 |
| 성공 | 저장 성공 | "✅ 알림 신청 완료" 화면에 이메일·받을 소식·빈도·문자 알림·바라는 점 요약 | "신청 내용 수정" 또는 "새로 신청하기" |
| 실패 (중복) | 이미 신청한 이메일 | "✗ 신청하지 못했어요. 이미 알림을 신청한 이메일이에요…" + 이메일 칸 오류, **입력 내용 그대로 유지**, 버튼 다시 활성화 | 주소를 고치면 오류 해제 → 다시 신청 |
| 실패 (저장 불가) | 브라우저 저장소에 쓸 수 없음 | "✗ 신청하지 못했어요. 이 브라우저에 저장할 수 없는 상태예요…" 입력 유지 | 잠시 후 다시 시도 |
| 수정 | 완료 화면에서 "신청 내용 수정" | 입력값이 채워진 폼으로 돌아가고 버튼이 "수정 내용 저장"으로 바뀜 | 저장하면 "✅ 신청 내용 수정 완료" |
| 다시 작성 | "다시 작성" / "새로 신청하기" | 입력값, 오류·안내 문구, 요약, 버튼 문구·상태, 문자 알림 영역(숨김·disabled) 모두 초기화 | 처음부터 입력 |

실패 처리 코드 위치: `script.js`의 `saveApplication()`이 중복 이메일이나 저장 실패를 확인해 오류를 던지고, `handleNotifySubmit()`의 `catch` 부분이 입력값을 유지한 채 실패 안내를 보여 줍니다. 신청 정보는 브라우저 `localStorage`(`amor-notify-list`)에 저장됩니다.

## 중간고사: 내 답장 보관함

### 중간고사에서 새로 추가한 것

7주차 "AI 답장 상담" 흐름의 **끝(완료 화면)**에 **내 답장 보관함**을 연결했습니다.
추천받은 답장을 메모와 함께 저장하고, 보관함에서 키워드·관계 상황으로 찾아 다시 열거나, 저장한 내용으로 상담을 다시 이어가거나, 삭제한 뒤 되돌릴 수 있습니다.

## 서비스와 사용자

| 항목 | 내용 |
|---|---|
| 주요 사용자 | 연인·썸 상대에게 보낼 답장이 고민되는 20~30대 |
| 서비스 목적 | 대화와 상황을 이해해 관계에 도움이 되는 말을 추천 |
| 사용자 목표 | 내 상황에 맞는 답장을 추천받고, 보낼 때 다시 찾아 쓰기 |
| 주요 행동 | ① 고민 입력 → 상황·톤 선택 → 추천 받기 ② 보관함에 저장 → 찾기 → 열기·다시 상담·삭제 |
| 완료 조건 | 상담: 완료 화면에 추천 답장 표시 / 보관함: 저장한 답장이 목록에 나타나고 다시 열 수 있음 |

## 전체 사용자 흐름

```
[7주차] 시작 → 입력 → 선택 → 확인 → 완료
                                      ↓ (중간고사)
                              보관함에 저장 (메모 선택)
                                      ↓
               내 답장 보관함: 찾기(키워드·상황) → 열기
                                      ├─ 이 내용으로 다시 상담 → [7주차] 확인 단계로 이동
                                      └─ 삭제 → 되돌리기
```

## 중간고사 보관함: 행동 → 조건 → 반응 → 다음 행동

| 사용자 행동 | 확인할 조건 | 성공 반응 | 다른 분기의 반응 | 다음 행동 |
|---|---|---|---|---|
| 완료 화면에서 "보관함에 저장" | 메모 20자 이내인가 | 초록 안내 "보관함에 저장했어요! 지금 N개", 버튼이 "저장 완료"로 바뀌고 비활성화, 보관함 목록 맨 위에 추가 | **오류:** 21자 이상이면 "메모는 20자 이내로 줄여 주세요. (지금 N자)" + 빨간 테두리, 저장 안 됨 | 보관함에서 확인 또는 다시 상담하기 |
| 같은 고민·같은 답장을 다시 받음 | 이미 보관함에 있는가 | – | **중복:** 주황 안내 "이미 보관함에 저장된 답장이에요", 저장 버튼 비활성화 | 보관함에서 기존 항목 열기 |
| 보관함 키워드 입력 / 관계 상황 선택 | 메모·고민·답장·닉네임에 키워드가 있고 상황이 맞는가 | 맞는 카드만 표시, "전체 N개 중 M개 표시" | **결과 없음:** "'키워드' · 상황 조건에 맞는 답장이 없어요. 다른 키워드를 입력하거나 '전체'로 바꿔 보세요." + "검색 조건 초기화" 버튼 | 조건 초기화 후 다시 찾기 |
| 보관함이 비어 있을 때 | 저장된 답장이 있는가 | – | **비어 있음:** "아직 저장한 답장이 없어요…" + "상담하러 가기" 버튼 | 상담 영역으로 이동 |
| 카드의 "열기" | 해당 항목이 존재하는가 | 상세 영역에 메모·상황·톤·닉네임·고민·답장 표시, 카드 강조 + "열려 있음" | – | 닫기 / 삭제 / 다시 상담 |
| "이 내용으로 다시 상담" | – | 저장한 닉네임·고민·상황·톤이 상담 흐름에 채워지고 **확인 단계**로 이동 | – | "이전"으로 톤을 바꿔 새 답장 받기 → 다른 답장이면 새로 저장 가능 |
| "삭제" | – | 목록에서 사라지고 "'…' 답장을 삭제했어요. [되돌리기]" 표시, 열어 둔 항목이면 상세 닫힘 | **취소:** 삭제한 답장이 지금 완료 화면의 답장이면 저장 버튼이 다시 활성화 | 되돌리기 또는 계속 사용 |
| "되돌리기" | 직전에 삭제한 항목이 있는가 | 원래 위치로 복구, 완료 화면 저장 버튼도 "저장 완료"로 돌아감 | – | 계속 사용 |
| "다시 상담하기" | – | 상담 입력·선택·오류·저장 상태 초기화, 1단계로 | 보관함 목록은 유지 (다른 흐름이므로) | 새 상담 시작 |

보관함은 브라우저(localStorage)에 저장되어 새로고침해도 유지됩니다.

## 7주차 상담 흐름 (기존 유지)

| 단계 | 사용자가 하는 일 | 조건과 반응 |
|---|---|---|
| ① 시작 | "상담 시작하기" | 입력 화면으로 이동 |
| ② 입력 | 닉네임(필수), 고민(필수, 10자 이상) | 비었거나 짧으면 빨간 오류 문구, 다음으로 못 넘어감 |
| ③ 선택 | 관계 상황, 답장 톤 | 미선택 시 오류 문구, "이전"으로 가도 입력값 유지 |
| ④ 확인 | 요약 확인, "고민 수정"·"이전"으로 수정 | 수정한 값이 확인 화면에 다시 반영 |
| ⑤ 완료 | 추천 답장 확인 → **보관함에 저장(중간고사)** / 다시 상담하기 | 상황 3 × 톤 3 = 9가지 답장 |
